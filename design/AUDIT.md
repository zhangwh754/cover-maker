# 小红书封面设计审查

日期：2026-10-23。初始审查为 Audit；用户随后选择 A「大图推荐」，明确只需要类型、标题和一段描述。现进入 Bootstrap + Calibrate，并创建 `DESIGN.md`，实现移动端及桌面渲染改版。

## 范围与证据

用户反馈封面引流效果不佳，主要发布平台为小红书。本次检查输出封面，编辑器交互不在范围内。依据为 `src/config.ts`、`public/local-render.js`、`src/overlay.ts`。技术栈为 Vite、原生 JS、Canvas 和 Capacitor；桌面 CLI 使用 Sharp/SVG。字体为 Noto Serif SC、Noto Sans SC。

## 事实

- 输出 1080×1440，原图框 805×925，仅占画布约 47.9%。contain 模式遇到宽图还会产生框内留白。
- 左侧栏目竖排，原图起点 x=205，占用较多横向空间；作品标题位于 y=1190 或 y=1152/1224。
- 单行标题字号 50–70；缩至 180px 宽时约为 8.3–11.7px。分类 27、英文页脚 16，缩略图中辨识较弱。
- 米白底、衬线标题、细边框、编号形成统一的编辑出版风格；缺少明确的推荐理由字段，当前副标题允许自由输入。
- 手机和服务端渲染分开实现；改模板时需同时处理或明确仅支持移动端。

## 推断

当前版式有利于系列归档和气质统一，但在陌生用户快速浏览时，可能较难识别“作品是什么”和“为什么值得看”。这是设计假设，尚无曝光、点击、阅读、收藏及关注数据证明因果。

## 原方案对比（用户已选择 A）

1. 大图推荐：图像主体占据大部分画面，底部深色渐变上放作品名及一句具体推荐理由。适合画面辨识度高的动漫、游戏、影视推荐。文字与人脸、画面自带标题避让。
2. 编辑推荐：保留米白底和刊物气质，移除独立竖排栏，图片横向扩展；作品名更大，推荐理由紧邻标题。适合原图文字较多、需要完整保留海报的内容。建议优先试用。
3. 观点大字：上半幅突出一个有内容支撑的观点，下半幅图片作为证据和作品识别。适合测评、攻略、盘点；不宜所有单作推荐都套用。

三者共享：作品名、推荐理由、可选角标、图片焦点和模板选择。建议主标题每行约 6–10 个汉字、最多两行，超长时提示编辑，避免一味缩小；这是拟议约束，不是平台规则。预览需加入约 180px 宽缩略图检查。

## 实施与验证

图片框已扩展为全画布，默认铺满；栏目竖排、编号和英文页脚已移除。原副标题输入改称描述，不新增第二段描述。编号保留在文件名与历史记录中。标题、描述的换行和位置计算已提取到共享模块，减少 Canvas/SVG 布局分歧。原出版风格属于已替换的历史方案；旧历史图片不重绘。

Node 回归测试通过 18 项，覆盖三种文字、无栏目和编号、渐变存在、焦点裁切、长标题以及既有生成与编号行为。浏览器和 APK 验证结果见本次交付说明；本记录不声称已验证点击率或手机系统分享。

## 未知与验证边界

对比稿为相同示例文案、相同抽象占位图的布局示意，不代表真实作品画面。没有模拟信息流、没有 APK 实机截图或点击效果验证。

未知：真实发布封面、目标读者、内容类别占比、账号曝光来源、点击率、收藏率、关注转化。曝光不足和点击不足需要分开诊断，封面改版不能直接保证关注增长。

先用编辑推荐和当前版式在相近选题上交替试验，尽量固定内容类型、发布时间段等条件。比较平台实际提供的曝光与阅读/点击指标，关注收藏与关注转化；少量笔记只能初步判断，不应声称严格随机 A/B 或承诺提升比例。
